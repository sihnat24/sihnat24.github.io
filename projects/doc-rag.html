Overview

What it is & why

This project is a work in progress. The goal is to build a general-purpose agentic system for document intelligence — one where a model can ingest a heterogeneous corpus of documents and call the right retrieval tools to answer questions grounded in the actual content.

Rather than a fixed retrieval pipeline, the system is designed around an agent that decides how to answer: querying a vector store, looking up structured data, or explicitly declining when the answer isn't in the corpus. The last behavior is intentional — for high-stakes use cases, a confident wrong answer is worse than no answer at all.

Document types supported so far include PDFs, spreadsheets, and web-scraped policy pages. The architecture is fully local with no cloud dependency.

Technical Approach

Architecture & decisions

Ingestion & chunking. Documents are split using recursive text splitting, tuned per document type. A layout-aware PDF parser detects multi-column academic formatting from word coordinate geometry and crops columns before extraction — standard parsers produce garbled text on two-column papers.

Embeddings & retrieval. Chunks are embedded locally with sentence-transformers and stored in a persistent Chroma vector database. A multi-collection architecture keeps distinct document corpora separate, which matters when you want to scope retrieval to a specific knowledge base.

Agentic layer. Built on Ollama (local LLM inference). At query time the model selects among available tools — vector retrieval or a structured CSV query tool — or declines if nothing relevant is found. A LangChain agent layer adds cross-encoder re-ranking on top of initial retrieval, improving result quality for longer or ambiguous queries.

Eval framework. Hand-authored questions across three buckets: single-document lookup, cross-document synthesis, and trap questions designed to test explicit declination. This is how the "refuses to hallucinate" behavior gets verified rather than assumed.

Status

Current state & next steps

Work in progress. The core RAG pipeline, multi-collection Chroma store, layout-aware PDF parser, and LangChain agent with re-ranking are all functional. The eval harness has a working question set across all three buckets.

The main thing being developed now is expanding the tool set available to the agent — adding more document types, richer metadata filtering, and better multi-hop reasoning across collections. The longer-term goal is a general agentic workflow layer that can be pointed at any document corpus.
