Overview

What it is & why

A computer vision security system built around YOLOv8 pretrained on COCO, meaning person, dog, and car detection work out of the box with no training required. The model is the detector underneath — the real project is the infrastructure layered on top: persistent cross-frame object identity via ByteTrack, configurable zone alerting, loitering detection, and automatic clip recording triggered by suspicious activity. The system targets a Raspberry Pi as its final deployment platform, accepting either a local webcam or an RTSP stream from a Pi camera as input.

The motivation was to build a realistic security tool rather than a demo. Most CV tutorials stop at drawing bounding boxes. This project pushes past detection to handle the harder problems: what happens when the same person walks in and out of frame, how do you define a restricted area in pixel space, and how do you record footage before an alert is triggered so you don't miss the moment that caused it.

Technical Approach

Architecture & decisions

The pipeline is a single loop: read a frame from the source, run YOLOv8 with ByteTrack enabled, check each tracked object against defined zones, update state, and write the annotated frame to a rolling buffer. ByteTrack assigns a persistent integer ID to each object across frames using a LAP solver for assignment, which makes identity-dependent logic like loitering detection possible. Without tracking, you only know that a person exists in a frame — not that it's the same person who was there three seconds ago.

Video sources are abstracted behind a common interface (stream) with read(), close(), and fps / frame_size properties. Concrete implementations exist for a local webcam (WebCamSource) and a Raspberry Pi camera stream over HTTP (RaspberrySource). Swapping between them requires a single line change.

Zones are defined as arbitrary polygons in pixel coordinates. Each frame, a tracked object's center-bottom point is tested against the polygon using OpenCV's pointPolygonTest. The zone draws green when clear and red when triggered. Zone state is tracked per object ID, so entry and exit events are logged with timestamps only on state transitions — not once per frame.

The loitering system uses a 20-second rolling frame buffer (a fixed-size deque). When an object remains inside a zone beyond a configurable threshold, it flushes the pre-event buffer to a timestamped MP4 file and continues recording until the object exits. This ensures clips always capture what happened before the alert, not just after.

Results

Outcomes & next steps

The system runs end-to-end on a laptop webcam, detecting and tracking people, dogs, and cats in real time with stable per-object IDs across frames. Zone entry and exit events are logged correctly, and the pre-buffer clip recording triggers reliably on loitering. Annotated clips are saved locally with timestamps for review.

The next step is deploying to a Raspberry Pi with a dedicated camera module. Planned extensions include a Telegram or email alert on loiter detection, multi-zone support with independent thresholds per zone, and a re-identification module so the same person can be recognized across disconnected sessions.
