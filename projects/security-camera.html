Overview

What it is & why

A neighbor's Ring camera caught a biker hitting our car and drove off. Without it, we would have had nothing. It made me want to buy one, until I looked into the subscription cost.

This project is my attempt at a local alternative. It uses YOLOv8 pretrained on COCO for person, dog, and car detection with no custom training required. Built on top: persistent cross-frame identity via ByteTrack, configurable zone alerting, loitering detection, and pre-event clip recording so footage exists before the alert fires.

Technical Approach

Architecture & decisions

The system uses a Raspberry Pi 5 as a dedicated camera node, streaming live footage over the local network to a laptop via MJPEG HTTP. The laptop handles all the heavy lifting. Each frame is run through YOLOv8n, a pretrained object detection model, which identifies people, animals, and vehicles in the scene. ByteTrack then assigns each detected object a persistent ID across frames, so the system can follow a person as they move through the frame rather than treating them as a new detection every second. Zones are defined as polygons drawn on screen, and each tracked object's foot position is checked against those zones to determine if someone is standing inside a defined area.

On top of that tracking layer sits the event logic, which is where the system decides what actually matters. Each tracked object has its own timer, and if it stays inside a zone long enough it triggers a loitering alert. When that happens, the system dumps a rolling buffer of the previous several seconds of footage to disk and keeps recording until the person leaves, producing a clip that includes what happened before the alert fired. Every event — entries, exits, and loiters — gets written to a structured log with a timestamp, the type of event, and which zone it happened in.

Results

Outcomes & next steps

The core pipeline works. The system correctly detects and tracks people across frames, fires loitering alerts when someone lingers in a defined zone, and saves timestamped clips with pre-event context to disk.

There are two directions left to develop. The first is technical: the clip writer briefly freezes the live feed when recording starts, a threading issue that needs a proper fix before the system can run reliably. There is no audio, which matters more than it sounds — a microphone is often the only way to catch events that have no visual warning, like a break-in at 3am. The bigger structural gap is that inference still runs on a separate laptop. A real camera runs independently, handles its own recording, and pushes footage to the cloud without being tethered to anything. The Pi needs to do all of that on its own, which requires purchasing a dedicated AI accelerator for it. The second is usability. There is no interface for viewing or managing recordings, which makes it essentially unusable for anyone who did not build it. A simple app for browsing, playing back, and clearing clips is the minimum before this could be handed to someone else.

Those pieces — threaded writing, audio, on-device compute, cloud upload, and a viewer — are what separate this from something you would actually install at your front door.
